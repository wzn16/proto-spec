# 像素判据（G8）

> 读时机：有截图后（步骤 5.5 与交付前）。`scripts/check_pixels.py` 在截图上直接量，不靠眼。

## 能测什么

| 指标 | 方法 | 阈值 | 对应缺陷 |
| --- | --- | --- | --- |
| 锚线数量 | 逐行取文本墨迹左缘，聚成簇（容差可配，默认 4px） | ≤ max_anchors（默认 4） | 表内文本与卡片标题不同线 |
| 文本贴边 | 卡片右边界左侧 3px 内是否有墨迹 | 0 处 | 末列文字贴边/被裁 |
| 强调色面积 | 高饱和像素占比 | ≤10% | 蓝色泛滥、焦点分散 |
| 实心强调块 | 连通块计数（≥300px） | 仅报告（主操作超量由 G6 执法） | 账号胶囊、多个实心按钮抢焦点 |
| 字号层级 | 竖笔画连续长度分档（占比 ≥2%） | ≥3 档 | 层级不足、"一样大"的页面 |
| 右缘留白 | 卡片边线（取最长连续段）与区间内最右墨迹的距离 | ≥12px | 末列贴边、内容压边框 |
| 行距方差 | 相邻文本带顶部间距的中位数与标准差之比 | 只报告 cv | 行高忽高忽低、密度不齐 |

## 局限性（必须知道）

1. 不做 OCR：测不出错别字、数字格式（1,786 vs 1786）、文案语气——这些靠 G6 与人工。
2. 深色底/渐变会让"墨迹"判定失真：顶栏与页签区域已被排除，若页面为大面积深色需调 `INK_LUMA`。
3. 锚线只统计左缘；右缘对齐需另测（当前靠 `detail-rules` 的列宽档位保证）。
4. 半字形（一个字的右半被裁）只能在截图上看到笔画断裂；本脚本用"贴边"间接覆盖，阈值 3px。

## 怎么读结果

- `锚线 1–3 条` 正常；`4 条` 说明有一处没归位，配合 `g8-pixels.json` 的 `anchors` 定位 x。
- `强调 0.2–1%` 属于克制；`>5%` 就要问"这些蓝色是不是都在承载同一个语义"。
- `字号 3–4 档` 是后台常态；`2 档` 往往意味着标题与正文没拉开。

## 变化追踪（不进门的工具）

`scripts/diff_shots.py --before a.png --after b.png`：32px 网格对比两版截图，输出变化面积、变化区块 bbox、以及指标变化
（锚线 / 强调面积 / 实心块 / 字号层级 / 问题数）。用在调优循环里判断"这轮改好了还是改坏了"，
**不参与 G5 放行**——它回答的是方向问题，不是合格问题。
