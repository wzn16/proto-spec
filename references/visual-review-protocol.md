# 独立评审协议（Peer Review）

> 读时机：自评评分单写完后、交付前。目的：用**没有参与制作**的第二双眼睛复核，避免自评手软。
> 来源思路：oil-ui `visual-review.md`（MIT），按 proto-spec 的门禁改造。

## 一、什么时候必须派

| 情形 | 是否派发 |
| --- | --- |
| 新页面 / 改版（骨架或视觉有实质变化） | **必须** |
| 交付前最后一轮 | **必须** |
| 单处间距/颜色微调 | 不必，自评即可 |

没有可派发的隔离执行者时：在自评单写「未独立评审 + 原因」，G7 允许放行但交付说明要标注。

## 二、交接清单（给评审者的，不多不少）

**必给**：
- 截图路径（三档尺寸 + 全页；注明设备视口）
- 用户原始任务与约束（品类、使用场景、品牌要求）
- 评审标准：`references/visual-scorecard.md` 的六维与锚点、`references/design-knowledge.md` 的三秒测试与默认做法清单
- 截图工具的 lint 提示（`qa/reports/*.json` 里的 `lint` 字段原样给）

**绝不给**：
- 源代码、页面实现细节
- 制作方的自评分数与辩护
- 上一轮评审分数（评分必须独立）

## 三、评审者要输出什么

文件：`<项目>/qa/visual-review-peer.md`，结构同自评单（三秒测试 / 锚线 / 六维打分 / 改进项 / 保留 / 结论），另外加一节：

```
## 分歧
- 维度 X：自评 ? 分 vs 他评 ? 分 → 差异原因……
```

评审者**只评审不修改**；没有明显问题就直说，不为凑数提意见。

## 四、制作方怎么处理反馈

1. 先看「重做」类结论：若首屏骨架被判为模型默认模板，回方向卡重定骨架，不逐条修补。
2. 按清单顺序改（影响大的先改），只改最低分维度，一轮 ≤4 处。
3. **分歧 ≥2 分的维度必须处理**：要么改，要么在自评单写「不采纳 + 理由」。
4. 「保留」一行的内容，改的时候对照，别把它磨平。
5. 双方审美僵持且无可见收益时，保留最佳版本并停止循环，写明原因。

## 五、G7 机检如何把关

`scripts/check_visual_review.py` 会检查：
- 自评单完整 + 六维 ≥4 或写了不采纳理由；
- 存在 `qa/visual-review-peer.md`（或自评单写明「未独立评审」）；
- 两份评分单同一维度分差 ≥2 时，必须出现「分歧」小节。
