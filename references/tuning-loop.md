# 调优循环（Tuning Loop）

> 这个 skill 不提供「标准样子」。它提供：访谈定基调 → 生成 → 截图评 → 按判据调 → 再截。
> 目标是让每一版比上一版**更好**，而不是让所有项目**更像同一个模板**。

## 一、循环（每轮 15–30 分钟）

1. **生成最小可评版本**：一页真实内容 + 真实数据规模（假数据但真密度），不做无数据的空壳。
2. **截图三档**：1440 / 768 / 375，全页与首屏各一张。
3. **按六维打分**（每维 1–5 分，写一句依据；<4 分必须改）：
   - 层级：3 秒内能否看出「页面标题 → 区块 → 主体 → 辅助」四级？
   - 节奏：留白是否成组（不是每处 16px 平均用力）？
   - 焦点：首屏是否只有 1 个视觉焦点？强调色面积是否 <10%？
   - 密度：数据密度与信息重要性是否匹配（重要处松、次要处紧）？
   - 一致性：同类元素是否同规格（按钮/输入/标签/间距）？
   - 可信度：去掉业务文案后，它像不像真实产品而非模板？
4. **只改最低分维度**，一次不超过 4 处改动，再截图对比。
5. **记录结论**：写进项目 SPEC 的「设计决策」段，一行一条（为什么这么改），不写死数值。

## 二、六维评分细则（每档给一句话依据）

| 维度 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 层级 | 标题与正文同重，看不出主次 | 能分出标题/正文，辅助信息偏弱 | 四级清晰：标题 → 区块 → 主体 → 辅助，且不同级用不同手段（字号/颜色/字重）区分 |
| 节奏 | 所有间距近似，页面像平铺 | 卡片与卡片间有呼吸 | 留白成组：组内紧、组间松，视线路径有起承 |
| 焦点 | 多处抢眼，强调色铺满 | 有主操作但不突出 | 一屏一焦点，强调面积 <10%，视线落点明确 |
| 密度 | 与任务不匹配（审计表格像表单） | 可读但偏挤或偏散 | 信息重要处松、次要处紧，规模感与任务匹配 |
| 一致性 | 同类控件不同规格 | 大体一致，个别例外 | 全站同规格，例外处有理由（如危险操作） |
| 可信度 | 像配色练习稿 | 像模板 | 像真实上线产品（数据结构、文案、边界态都合理） |

## 三、常见病与处方（诊断用，不是规范）

| 症状 | 成因 | 处方方向 |
| --- | --- | --- |
| 「扁平、没层次」 | 所有文字同色同重、所有间距同值 | 拉开 4 级字号与 3 档间距；次要信息降对比而非降字号 |
| 「像模板」 | 平均用力、每个卡片都有标题栏、每种语义都用色 | 删掉不必要的容器；强调色只给主操作与选中 |
| 「挤」或「散」 | 密度与信息重要性错配 | 主数据区放松、辅助信息收紧；表格行高随列数与任务调整 |
| 「不对齐」 | 数字未右对齐、列宽靠内容撑 | 定对齐规则再定列宽；用最小宽度而非固定宽度 |
| 「灰蒙蒙」 | 边框与分隔线过多、阴影滥用 | 减少分隔线，用留白分组；阴影只给浮层 |
| 「重点不明」 | 每个区块都想强调 | 一屏一焦点；次级信息用弱化（不是加粗） |

## 四、何时停止

- 六维均 ≥4 分且连续两轮无 <4 分项；
- 或改动开始只影响细节（<1 分钟能说清收益）时收手；
- 每轮都留截图与结论，作为下个项目的参考，而不是当成标准。

## 五、与家族/组件/旋钮的关系

家族（F0–F7）给气质方向，`references/design-knobs.md` 给强度旋钮，组件库给可选零件，调优循环决定**这一次**的取舍。
同一个家族可以长出不同的台账：形态、密度、强调面积、留白风格都可不同——
差异写在 SPEC 的设计决策里，而不是回到 skill 里改组件。
