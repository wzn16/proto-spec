# SPEC.md 章节结构与填写规则

> 上级入口：SKILL.md 步骤 2/3。实际骨架文件是 `starter/SPEC.md`（复制到项目后填写）。
> 本文件只讲每章的职责、填写规则和一致性要求；不重复骨架内容。

## 章节职责

| 章 | 职责 | 填写规则 |
| --- | --- | --- |
| §0 元信息 | 版本、状态机位置、冻结日期、来源引用 | 每次解冻改版：版本 +0.1，状态与日期同步更新 |
| §1 产品语境 | 类型 / 用户 / 设备 / 气质关键词 | 即访谈 G0 的结论，逐字记录 |
| §2 色彩系统 | 主色阶、语义色、中性阶、表面与文字映射、对比度 | 全部用 tokens 变量名表述，值写在 tokens.css；正文对比度 ≥4.5:1 需实测备注 |
| §3 字体排版 | 字体栈、字号阶梯表（档位→用途） | 字号只允许 tokens 已定义档位 |
| §4 空间质感 | 间距刻度、圆角体系、阴影层级 | 标注每档的使用对象（如 --s-radius-card 用于卡片） |
| §5 组件规范 | 按钮/输入/导航/反馈/数据展示的关键约定 | 与 snippets-catalog 的类名一一对应，不另发明组件名 |
| §6 布局骨架 | 框架尺寸、栅格断点、页面结构标准 | 与 tokens.css 的 --c-* 几何值一致 |
| §7 交互保真度 | 等级、交互做/不做清单、假数据规范、动效 | 即访谈 G8 结论 |
| §8 页面清单与流程 | manifest（页面 id/路径/标题/类型/状态页）+ 站点地图树 + 核心流程 | manifest 是 G3 三方对账的基准，页面集合变更必须先改这里 |
| §9 生成契约 | 技术约定、token 引用规则、生成后自查清单 | 生成每页前按 §9 组装上下文 |
| 附录 A | token 完整清单（变量名/值/用途） | 与 tokens.css 同步维护；冲突以 tokens.css 为准回改本文档 |
| 附录 B | 访谈决策记录（题号/默认值/最终选择/理由/来源） | 访谈时逐题追加，支持新项目整包继承 |

## 一致性规则

1. SPEC 中出现的每个值都必须能对应到 tokens.css 的一个变量；对不上就补 token 或改值。
2. §8 manifest 的页面集合 = pages/ 目录实际 .html 文件集合 = index.html 链接集合，三方必须一致（G3 强制）。
3. 冻结（frozen）后本文件只增不改；确要改走 SKILL.md 步骤 5 的规范级通道（版本 +1 + changelog）。
