# 骨架目录（Layout Patterns）

> 读时机：`design-from-brief.md` 第 3 步选骨架时。每个骨架给「结构图 + 适用 + 变体 + 错法」。

## 1. 台账（Ledger）
```
[页头 标题 + 主操作]
[KPI 0–4]（可选）
[筛选 ≤4 常驻 / >4 收更多]
[工具栏 批量 ｜ 密度 列设置 导出]
[表格 固定表头 + 冻结首列/操作列]
[分页 总数 每页 页码]
```
适用：记录维护型、单据处理型的列表入口。变体见 `patterns-ledger.md`。

## 2. 主从（Tree–Detail）
```
[左树 240–320，可搜索可折叠] [右 台账/详情]
```
适用：层级主数据、组织/目录/科目、分类导航明确的数据。
错法：左树太窄（<220 深层缩进挤死）、右表跟着树重渲染丢失筛选条件。

## 3. 看板（Board）
```
[列1 待处理] [列2 进行中] [列3 已逾期] [列4 已完成]
每列：列头（名称 + 计数）→ 卡片（标题 + 责任人 + 时限 + 状态）
```
适用：流程跟踪型、任务分派、有时限的工作。
错法：列数 >6（横向滚动失去全貌）、卡片塞超过 4 行信息。

## 4. 概览（Overview / 分析）
```
[KPI 带 2–6 张，每张 = 指标 + 变化 + 迷你趋势]
[主图表 1–2 个，占 2/3 宽]
[侧栏：Top 列表 / 异常清单]
[下钻入口：点指标 → 台账（带筛选）]
```
适用：分析决策型、给管理层的第一屏。
错法：图表多于 4 个、KPI 全是累计值无同比、点了不联动。

## 5. 详情页（Detail）
```
[返回 + 实体标题 + 状态 + 主操作]
[摘要区：3–6 个关键字段横排]
[分页签：基本信息 / 关联记录 / 操作日志 / 附件]
[底部：流转操作条]
```
适用：单据处理型的主对象、需要长期引用的记录。
错法：把 20 个字段平铺成一列、日志与附件挤在基本信息里。

## 6. 向导（Wizard）
```
[步骤条 ≤4：1 基本信息 → 2 明细 → 3 校验 → 4 提交]
[当前步表单 + 上一步/下一步/保存草稿]
```
适用：录入字段 >20 或跨角色协作的创建流程。
错法：步骤 >4、无法回退、中途丢失已填内容。

## 7. 配置页（Settings）
```
[左侧分组（≤8 组）] [右侧该组表单，逐项说明 + 保存]
```
适用：参数/字典/权限配置。
错法：全站参数一屏堆完、保存按钮只在底部（长页够不到）。

## 8. 单页工具（Tool）
```
[输入区（左/上）] [结果区（右/下）] [动作条]
```
适用：计算器、转换器、批量处理、树形查看器。
错法：输入与结果混排、缺少"重置/清空"。

## 组合规则

- 一个模块可由 2 个骨架组成（台账 + 详情抽屉；概览 + 台账下钻），但**同一时刻只呈现一个主骨架**。
- 骨架决定后，密度/圆角/色温只由旋钮决定，不改骨架。
- 新需求的骨架若不在目录中，先写清结构图与适用判据，再加入目录——不要临时拼凑。
