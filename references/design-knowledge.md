# 视觉判断知识（吸收自 oil-ui，MIT，已按 B 端原型适配）

> 读时机：步骤 4 生成界面后、交付前评审前。这里给**判断标准**，不是样式方案。
> 来源：oil-ui `references/visual-language.md`、`reviewer-manual.md`（MIT, oil-oil），重新组织并收敛到后台原型场景。

## 一、焦点与空间

- 每个区域一眼能认出**最重要的那条信息或动作**；其余用更小字号、更轻字重、更低对比退后。不让几种强调同时抢。
- 同一关系用同一间距；组内紧、组间松。**先用对齐和留白立结构，再考虑容器与分隔线**。
- 先直接放内容，只在真需要分组/选中/操作范围时才加容器——**不要页面套模块、模块套卡片、卡片套条目**。
- 分隔线与边框不重复：留白已分开处不补线；同一处分隔不叠双线；线粗对应层级（粗分版面、细分栏），全页一致。
- 区域之间由父布局管，组件只管自身内部空间；同一段距离不要多层各加一遍。

## 二、文字角色（B 端取值）

| 角色 | 字号 | 行高 | 用法 |
| --- | --- | --- | --- |
| 页面标题 | 20 | 1.3 | 一页一个 |
| 区块/卡片标题 | 14 | 1.4 | 半粗 |
| 正文/表格 | 13–14 | 1.5 | 高密度工具可 13 |
| 辅助/表头 | 12 | 1.5 | 次级色 |
| 数字 | 等宽 | — | 需要纵向比较时用等宽数字 |

- 层级差别要**够大**：标题与正文靠字号+字重+颜色三者中的两项拉开，不只靠颜色。
- 中文断行主动控制：数字+单位用不换行包住；行末只剩 1–2 个字、或词被拆行算缺陷。
- 名称不要用固定高度裁；必须截断时给查看完整内容的入口（title/详情），且截断后仍能区分。
- **示例数据要像真的**：避免整数指标（1,000 / +10%）、张××李××、每条都是"2 小时前"、写着"标题/描述"的占位字。真实数据是不整齐的（1,238 / +1.83% / 昨天 16:12）。

## 三、控件语法一致

- 圆角、描边、字重、按下位移、选中表达、状态图标，在按钮/输入/标签/开关/空态之间同一套逻辑。
- 能点的要看得出来，点了要有反馈；默认/按下/聚焦/选中/禁用/处理中形态各不相同。
- 只在 hover 出现的入口，触屏与键盘也要能到达。
- 图标：一个产品一套库；描边粗细跟字重走（细字 1–1.5px，粗体 2px+）；尺寸约字号 1–1.25 倍，按视觉中心对齐；陌生图标配文字；箭头 ↗ 只表示跳转外部，不用于原地提交。

## 四、评审：三秒测试 + 六项缺陷 + 打分

### 三秒测试（最先做）
把首屏缩到 480px 宽看三秒，写下两句：**像哪一年的哪一类产品**、**第一眼看到什么**。
像"若干年前的通用产品/组件库默认样式"的，直接判不合格（总分 ≤7）。

### 模型默认做法（见到即扣分）
- 每屏左上角都放 Logo+产品名，或品牌行下再叠页面标题，挤占任务空间；
- 处处圆角卡片 + 每个层级都画线框，画面发碎；
- 卡片/提示框随手加单侧彩色粗边线做装饰；
- 无来由的渐变、发光、Emoji 当图标；
- 配色没有产品依据（说不出为什么是这个色）；
- 四种等宽指标卡 + 满屏彩色胶囊的粗糙模板；
- 主体信息是"示例/待核实/系统界面"这类填充文字。

### 精致度（放大 200% 看）
- 顺着整页数所有标题与正文块的**左边缘 X 起点**：有秩序的版面共享 2–3 条垂直锚线；散成五六处即未对齐，点名哪几块。
- 字距行距、图标与文字对齐、阴影描边、各状态是否一致；100% 看中文断行与孤字。

### 设计感（缩略图看）
- 主角在 480px 缩略图里看不看得见、占多大。
- 把每屏构图概括成一个词（分栏/表格主从/看板上墙/概览仪表）；同一个词连续两次或全页三次 → 模板复读。
- 每屏只有一个主角；多出来的面板/数据/装饰点名删掉（删完主角没变强、只是变空 = 没删对）。

### 打分锚点（1–10）

| 分 | 门槛 |
| --- | --- |
| 9–10 | 主流程与异常态都成立，无阻断；至少一处达到品类最好水平 |
| 8 | 方向鲜明、流程通、缩到 480px 仍认得出；有若干中等问题 |
| 7 | 方向成立，但有一处会让用户丢数据/走错/卡住，或首屏仍是默认模板 |
| 5–6 | 能看出方向，骨架是默认模板，或主流程多处卡住 |
| 1–4 | 主任务走不通，或画面重叠/裁切/看不清 |

**任务优先于视觉**：会丢数据、走不通、骗用户"已成功"的问题，比任何视觉问题优先扣分。

## 五、与 proto-spec 已有的关系

- 本节补的是「好不好」；`tuning-loop.md` 给的是「怎么迭代」；`patterns-*.md` 给的是「骨架怎么搭」。

## 六、动效（吸收自 oil-ui motion，按原型收敛）

**每个界面先做三处**：① 主操作反馈；② 状态切换看得出「从哪来、到哪去」；③ 首次进入的入场（原型里可以只做 ① 和 ②）。

**呼应四原则**：
1. 从被操作的地方出发（从按钮位置展开）；
2. 一次切换朝一个方向（不要上下左右各动各的）；
3. 主角先动，其余延后 40–80ms、幅度更小；
4. 形状接力（按钮展开成面板，列表项长成详情）。

**时长**：微交互 150–200ms；面板/抽屉 200–280ms；页面级转场 240–320ms；ease-out 起步。超过 320ms 在后台会显得拖。

**界面过渡三模式**（选一个，别混）：
- 遮罩式（最稳，适合结构无关的两页）；
- 交叠式（连贯但需两页共存，内存与层级要管）；
- 共享元素（最顺但最易错位，必须留退路：出错直接显示到位状态）。

`prefers-reduced-motion` 一律降级到 0.01ms，不做例外。

## 七、工具与证据（吸收自 oil-ui tools）

- **看一眼**：改完一批，只截当前这一屏，一条命令；页面没变不重复截。
- **取证**：送评审前、交付前各一次，取三档尺寸 + 全页 + 必要局部；首屏选方向那轮每方向只截一张。
- **比差异**：有参照物时用 `--compare` 出叠加图，先修差异最大的格，不凭印象宣布"对上了"。缩略图只能判构图，字号/间距/对齐要在 100% 下看。
- **lint 提示如何处理**：要改的 = 对比度不达标、正文 <13px、行高过紧、停在透明；可保留但必须写理由的 = 有色底上的灰字、超长正文行、标题上方眉标、卡片套卡片（看板列容器）、Emoji 图标。
