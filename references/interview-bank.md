> 上级入口：SKILL.md 步骤 2。目的：用最少的对话往返，把约 33 个设计决策问清、记全、可复用。

## 访谈协议

1. **批量提问**：一次一组，禁止逐题追问。组内用表格呈现「题 | 推荐值 | 备选 | 理由」，支持整组通过，也支持单点覆盖。
2. **钉子题必须显式表态**：G0 全组、G1-1 主色、G2-1 页面底色、G7-1 页面清单、G8-1 保真度。其余题用户回复「全默认」即整组通过。
3. **草图推断优先**：从草图提取的值按置信度处理——≥80% 直接作为推荐值；50–80% 推荐但附备选；<50% 不推荐，回退基准家族（F0）默认。每个值标注来源：`preset / inferred / user / default`。
4. **推导链**：G0-1 产品类型 → G2 底色、G4-4 密度、G6 骨架、G7 页面标准集；G0-2 设备 → G3 正文字号、G4-4 控件高度；G0-3 气质关键词 → 候选家族（默认 1 个推荐 + 1 个备选）→ 家族定义展开为整包推荐：G1-1 主色（家族默认值）、G2 背景与中性色（家族值）、G4-1 按钮形状（家族规则）、G5-1/2 圆角与阴影哲学（家族值）、G6-2 导航深浅（家族规则）、G8-4 动效性格（家族规则）；G0-4 品牌约束 → 覆盖家族「自由变量」（如主色）并重推色阶；触到「身份特征」即提示换家族（自由变量 vs 身份特征见 family-library.md）。
5. **风格未定**：先按 2–3 个候选家族各生成一张迷你示例页（同一骨架页分别挂载候选家族的 tokens.css + family.css）供用户挑选，选定后回到本题，把选中家族作为整包推荐。
6. **呈现纪律**：推荐家族时用「本项目的真实页面标题 + 真实数据」说明这个家族看起来怎样、操作起来怎样、为什么适合、代价是什么（如暗色家族打印不便），不展示家族菜单让用户学术语。
7. **细节与结构规则必须显式确认**：凡涉及页面组织结构（哪些页进菜单、表单是否隐藏页）与视觉细节（组件形态/位置/文案/布局对齐）的决策，
   用户没有明确给出的，必须批量询问得到答案后才能生成——宁可多问一轮，不许靠假设下手。有参照截图时以「元素对账单」承载此过程。
8. **需求溯源与推断标注**：用户提供需求文档/PRD 时，每个功能点标注来源（「来自需求第 X 条」）；
   推断出的功能必须标「推断」并经用户确认后才能纳入，禁止编造；同时识别「业务闭环缺口」
   （业务必须但需求未覆盖的功能），单独列出等确认。
9. **留痕**：每题最终结果记入 SPEC 附录 B（默认值 / 最终选择 / 理由 / 来源），家族登记行记录「家族 id + 版本 + 覆盖项清单」，供跨项目整包继承。

## 美学家族库

- 家族索引、治理规则（入库门槛 / 自由变量 vs 身份特征 / 版本 / remix 通道）见 `references/family-library.md`；家族定义四件套在 `references/families/F*.md`，按需只读选中的家族，不全家读入。
- F0 冷静企业·蓝：克制、可信、秩序感——不出错的企业默认（基准家族，即 `starter/assets/tokens.css` 当前值）。
- F1 墨纸编辑·黑白：纸面一样的白，墨一样的黑，一根细线分开世界。
- F2 暖陶人文·赤：暖米纸、赤陶土、衬线的呼吸——像精装书不像仪表盘。
- F3 数据驾驶舱·暗：深色玻璃舱，数字是唯一的主角。
- F4 终端机能·磷光：近黑底、等宽字、一根磷光青——回车键的秩序。
- 换家族方式：整体替换 tokens.css + family.css，并同步更新 SPEC §2.0（家族 id + 版本 + 覆盖项清单）与 §2–§5；类名、结构与脚本完全不变。
