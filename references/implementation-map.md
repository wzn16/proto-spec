# 设计 → 实现映射（Design-for-Code）

> 读时机：步骤 4 动手写页面之前，以及步骤 5.5 评审时。**每条设计决策必须能落到组件、token 或"新增原语"三选一。**
> 目的：避免"稿子好看、代码难写、维护崩溃"。

## 一、三条硬规则

1. **能用现有组件的，不许自定义。** 先查 `snippets-catalog.md` 与组件库工作台层；组件能满足 80% 就用组件 + 少量 `p-` 修饰。
2. **不能用组件实现的，先升级组件库再画。** 需要新原语（详情面板、分段器、纸条卡、时间轴）时：先在 components.css 加一层（token 驱动），再在页面使用。禁止页面里"一次性手搓"。
3. **每个视觉决策标成本**：低（改 token/类）/ 中（组合 2–3 个组件 + 少量 CSS）/ 高（新原语、伪元素、transform、嵌套滚动）。**成本高的必须有理由，且默认不做。**

## 二、成本分级速查

| 手段 | 成本 | 备注 |
| --- | --- | --- |
| 改 tokens（颜色/圆角/行高/间距档） | 低 | 首选 |
| 加修饰类（`--dense`/`--zebra`/`--pin-first`/`--label-left`） | 低 | 已有变体优先 |
| 组合组件（卡片 + 表格 + 描述列表） | 中 | 注意 flex `min-height:0` |
| 双栏主从 + 独立滚动 | 中 | 只在容器内滚动，整页不滚 |
| `max-width` 卡内容宽度 | 中 | **禁止**用来给表格限宽（会破坏锚线），改列宽/colgroup |
| 伪元素装饰（胶带/贴纸/角标） | 高 | 响应式与打印易崩 |
| `transform: rotate` 拟物（章/标签） | 高 | 仅静态展示页可用，业务页禁用 |
| 嵌套滚动（页面 + 卡片内） | 高 | 优先单一滚动容器 |
| 绝对定位拼版 | 高 | 一律不用 |

## 三、每个区块都要写映射

在 SPEC 或页面注释里逐块标注（评审会看）：

```
区块：节点详情
组件：c-card + c-data-table（--dense）+ p-detail 修饰
token：--s-space-5 / --s-border / --s-fs-small
新增：无
成本：中
```

## 四、常见「好看但难实现」清单（默认不做）

- 卡片浮起用多层阴影叠出"纸感" → 用 1px 线 + 背景差；
- 表格行悬停整行位移/缩放 → 只改背景；
- 表头与内容不共享列宽（视觉对齐靠 margin 硬凑）→ 用一张表；
- 侧栏折叠动画 + 内容重排 → 原型阶段用静态宽窄两态；
- 自定义滚动条通栏美化 → 只在长列表页做一处；
- 图标手工画 SVG → 用现有图标或字符。

## 五、原型阶段的实现边界（写进交付说明）

原型是 HTML/CSS/少量 JS，**不承诺**：真实分页接口、服务端排序筛选、权限控制、并发编辑、复杂动画编排。
这些在交付说明「已知限制」里列明，避免甲方按原型索要实现工期。
