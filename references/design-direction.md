# 方向探索（B 端原型版，吸收自 oil-ui design-direction，MIT）

> 读时机：步骤 2.5。用户没有指定方向、或只说"高级/专业/好看"时，**先出 2–3 个方向再动手**，
> 不要拿一个方向直接做完。方向是决策，不是装饰。

## 一、认品类，拆标杆

1. 说出品类（例如"质量整改跟踪后台""主数据维护工作台""审核台账"），以及这个品类里风格最鲜明的 2–3 家。
2. 能拿到真实画面就拿（截图存进项目 `qa/refs/`），对着图拆 6–10 条：控件形状与手感、字体、颜色、图标、状态反馈、动效、文案语气、首屏放什么。每条写「它是什么样 + 为什么这样」。
   拿不到画面就写明"未看图，凭记忆"，并把字体/色彩/主视觉标为待验证。
3. 分三样东西：**基线**（用户已期待的结构，沿用）、**套路**（品类人人都在用的默认版式，至少一个方向要打破）、**撞脸**（连字体配色都跟标杆一样，禁止）。

## 二、定调性（五刻度，每项写依据）

| 刻度 | 两端 | 画面上看什么 |
| --- | --- | --- |
| 能量 | 安静 ↔ 喧闹 | 饱和度、对比、元素是否碰撞 |
| 完成度 | 粗粝 ↔ 精致 | 边缘、噪点、对齐严格程度 |
| 密度 | 疏 ↔ 密 | 留白尺度、叠层、网格纪律 |
| 分量 | 轻 ↔ 重 | 字重、色块面积、阴影硬度 |
| 严肃度 | 活泼 ↔ 庄重 | 圆角、图形语言、动效幅度 |

证据指向高密度高对比，就不要交付"米色卡片 + 大留白"的模型默认。

## 三、模糊词必须翻译

| 模糊词 | 翻译成可观察决定 |
| --- | --- |
| 高级 | 先说是哪一种高级：字体对比、分隔方式、间距尺度、色相数量 |
| 精致 | 公差：字距、对齐网格、阴影级数、色相数量上限 |
| 克制 | 强调色面积 ≤10%、动效幅度上限、色相数量上限 |
| 大气 | 尺度：标题多大、主数据区占比、留白档位 |
| 简洁 | 密度档位 + 删掉什么（简洁是结果不是指令） |
| 专业 | 信息密度 + 对齐纪律 + 状态完整（空/加载/错误） |

翻译不出可观察决定的词，从理由里删掉。

## 四、生成引擎（B 端可用五种）

每个方向从一个**具体引擎**出发，不同方向用不同引擎：

1. **工作流证据**：从用户真实作业方式推（现场扫码 → 大按钮大字号；办公室对账 → 紧凑多列）。
2. **材质 × 环境**：车间金属与油污 → 硬边、低圆角、强分隔；洁净实验室 → 冷白、细线、低饱和。
3. **行业器物语法**：工单夹板、检验章、图纸标题栏、仪表盘刻度——借其结构，不贴图案。
4. **设计运动/文化传统**：瑞士网格（严格对齐、无装饰）、包豪斯（几何、功能色）。
5. **有意打破常规**：非对称分栏、无卡片化、极简到只有文字与线。

引擎决定结构、手感、质感；颜色单独按下一节定。

## 五、定色彩（三步）

1. 写两行：这个品类最顺手的默认配色是什么；标杆各占了哪个色相与明暗。
2. 每个方向定**不同色相家族**（不是"一亮一暗"），并用一句写它来自产品的什么（品牌资产/实物/使用场合）。至少一个方向跳出品类默认。
3. 至少三层：底色、主强调色、派生的选中底/描边/禁用态。黑白灰 + 一种强调色也算完整身份。

## 六、工作区骨架（B 端版"首屏骨架"）

先回答：**用户来这一屏是看什么、做什么？** 然后选骨架：

| 骨架 | 首屏长什么样 | 适用 |
| --- | --- | --- |
| 台账优先 | 页头 1–2 行 + 数据表第一排完整入屏 | 记录维护、对账 |
| 主从 | 左侧结构 + 右侧对象，两者同时入屏 | 层级主数据 |
| 看板上墙 | 4–6 列状态列，卡片即对象 | 流程跟踪 |
| 指标先行 | KPI 带 + 主图表 + 异常清单 | 分析决策 |
| 对象优先 | 当前对象与动作在首屏中心，列表退到侧边 | 处理单个单据 |
| 工具台 | 输入区与结果区同屏 | 计算/转换/校验 |

规则：导航+标题+筛选合计 ≤2 行；第一排内容必须完整进首屏；不放口号式说明段。
模型默认是"页头 + 四张等宽指标卡 + 表格"，一轮里最多一个方向用它，且要写理由。

## 七、方向卡（B 端精简版，写进 SPEC）

每个方向填一张，全部是具体选择：

| 字段 | 写到的程度 |
| --- | --- |
| 北极星 | 一句能指导取舍的意图（第一感受 + 围绕什么展开） |
| 调性 | 五刻度取值 + 依据 |
| 标杆与取舍 | 品类、拆的哪家、存图路径；沿用什么、换掉什么 |
| 生成引擎 | 哪一种，来自产品的什么证据 |
| 骨架 | 上表的一种 + 首屏能看到几个对象、页头几行 |
| 字体 | 字族/字重/尺度关系（展示、正文、数字） |
| 色彩 | 十六进制 + 用途 ≥3 层 + 来自产品什么 |
| 控件语法 | 圆角、描边、按下变化、选中表达，一句写清 |
| 动效 | 三处基本动效各怎么动（见 design-knowledge） |
| 结构性突破 | 改变首屏结构的那一处偏离常规 |
| 放弃什么 | 这个方向主动不要的常见做法 |

## 八、差异检验（出方向后自检）

- 同轮方向之间：骨架不同、色相家族不同、控件语法不同——**同一套只换色不算方向**。
- 每个方向能否用一句话说出"为什么这个产品该长这样"。
- 至少一个方向打破品类套路；任何方向不能撞脸标杆。
- 三个方向都要在三秒测试里认得出彼此不同。
