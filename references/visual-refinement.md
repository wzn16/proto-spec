# 视觉精修手册

> 上级入口：SKILL.md 步骤 5.5。方法提炼自界面设计方法论（层级/留白/字阶/色彩/控件语法/减法精修），按 B 端原型场景裁剪，结合本 skill 的 tokens 与组件体系。
> 核心纪律：**从组件库层修，不逐页打补丁**；品牌资产（如深色框架）保留；每次修改说得出「哪个元素、和谁的关系、怎么调、好在哪」——看源码能证明不一致，证明不了变好看。

## 精修原则

1. **焦点先行**：每个区域一眼认出最重要的信息或动作，其余靠更小字号、更轻字重、更低对比退后；不让几种强调同时抢注意力。
2. **同关系同间距**：一组之内紧、组和组之间松；先用对齐和留白立结构，再看需不需要容器和分隔线。
3. **线不重复**：同处分隔不叠双线；留白已分开的地方不补线；粗线分版面、细线分栏，全页一致。
4. **卡片不套卡片**：只有需要分组、表选中、拉开背景对比或划出操作范围时才加容器。
5. **从源头修**：改动落在 `starter/assets/components.css`（或项目的同层文件），精修的是组件实现质量，**不改 tokens 规范值**——那是设计决策，要走规范级通道。

## 逐维清单

### 字体与内容

- 文字角色固定五种：标题 / 正文 / 辅助 / 标签 / 数据，各用 tokens 字阶的组合工具类，层级差要够大。
- 表格是给人**扫视和比较**的：数字列等宽（`u-num`）、右对齐；名称列不截断，确需截断留完整内容入口，且相近名称截断后仍分得出谁是谁。
- 中文细节是交付门槛：孤字（行末剩一两个字）、不可拆词断行（「38 秒」「不会」）都算缺陷；多行中文标题行高 1.2–1.35，不照搬英文海报的极紧行高。
- 示例数据要像真的：数字不整齐（1,238 而非 1,000；+1.83% 而非 +10%）、时间格式多样（刚刚 / 昨天 16:12 / 3 月 14 日）、名字有长有短。整数指标和张三李四会暴露模板感。

### 空间与表面

- 层次不只靠明暗，可用色温/色相偏移区分表面；同层级的东西看起来一样重，内层轮廓与外容器协调。
- 状态不能只靠颜色区分（启用/停用要有文字标签，不只绿/灰）。
- 每种颜色有固定用处：文字、背景、动作、选中、状态，不混用。

### 控件语法

- 一套逻辑贯穿按钮/输入/标签/开关/空状态：圆角、描边、字重、按下位移、选中表达。换上主色后认不出是哪个产品 = 控件没进入方向。
- 状态彼此不同：默认 / 按下 / 聚焦 / 选中 / 禁用 / 处理中；状态变化时点击区域不变大变小、不挤动旁边布局。
- 图标一套画法：描边粗细跟字重走（细字配 1–1.5px），尺寸约为字号 1–1.25 倍，与文字视觉居中；内联 SVG 用 `currentColor`；能加快识别才用图标，陌生图标配文字。
- 箭头有含义：↗ 表示打开外部链接，原地提交动作不用它。

### 动效三处底线

- 主操作有反馈；状态切换看得出来路；首次进入有出场。
- 过渡统一 150ms（精修层已内置）；手感描述用「动作 + 实物参照」，不写形容词。

## 评审清单

每轮精修后逐项过，**先问题后提升，各最多 5 条**；每条写位置、证据、影响、修完的结果：

1. **偏离规范**：规范外颜色/字号/圆角，或绕过组件库手搓（G1 拦截 + 目检双保险）。
2. **布局结构**：最影响完成度的三处——层级、对齐、留白、减法。整页从上往下数标题与正文块的左边缘：有秩序的版面共享 2–3 条垂直锚线，散成五六处直接点名。
3. **精致度**：200% 放大看字距行距、图标与文字对齐、阴影描边、各状态是否一致；100% 看中文断行、孤字、数字格式。
4. **设计感**：页面主角在缩略图里可见吗？哪一块还是组件库默认样子、没有进入项目方向？页面是否进入所选家族的气质（按 SPEC §2.0 登记的家族禁忌与身份特征核对）？
5. **精简**：填缝文字（听上去有诗意但不指向任何对象的小字）、「示例」「仅供示意」类制作说明，逐条删。

最后一行写「**保留：…**」——点名一两处精修时不能磨掉的辨识度（如雷沃的深色框架、紧凑密度）。
